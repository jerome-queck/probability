# Root cause: PR #18 (agent-run.sh stability) needed 5+ review rounds

PR #18 replaced #17 (same `scripts/agent-run.sh` content, clean history). Counting #17, the
runner went through roughly a dozen verifier and review rounds before it was clean. This note
records what each failed round found, the cause they share, and the structural fix.

## Failed rounds

| Round | Finding | Fix |
| --- | --- | --- |
| #17 review r1 | Killing the agent left its process group running; the last parseable line was lost; only one verdict printed; a run with no result exited 0 | Process-group kill, keep last parseable line, print every verdict, exit 1 without a result |
| #17 review r2 | Detached grandchildren (setsid) survived the kill | Walk `/proc` descendants at signal time |
| #17 review r3 | A child reparented after a dropped connection escaped the kill | Remember descendants (pid + start time), group KILL |
| #17 verifier r4 | `ident()` aborted the runner under `set -e` when a child exited mid-scan | `ident` never fails; churn test |
| #17 review r5 | A torn `model_call_id` line blocked resume; an unguarded per-pid `kill` could abort under `set -e` | Match only explicit model keys; `kill … \|\| true` |
| #17 verifier r7 | A lint directive in a comment tripped the forbidden-string check, also in branch history | Replaced by #18 on a clean history |
| #18 review r1 | A torn line with an escaped model key or a spaced verdict was silently dropped | Stricter torn-line check |
| #18 review r2 | Replayed Task `started` events kept the stall watchdog off; assistant-line verdicts were lost after a resume | Open tasks keyed by `call_id`; verdicts read from assistant text too |
| #18 review r3 | The screenshot shrinker rewrote fresh smoke screenshots before the pixel compare read them | Shrink only files settled for 10 s and not under an active smoke run |
| #18 verifier r4 | Any command line that merely mentioned the smoke driver (including the agent's own prompt) counted as a running smoke run, so nothing was shrunk | Match the driver in argv plus a `smoke` argument |

Separately, the 900 s stall watchdog killed review runs that were waiting on Task subagents
(#13 review r3 exited 143), which is what prompted the 1800 s / open-task rule in this PR.

## Shared root cause

`agent-run.sh` grew from a thin wrapper (pick a model tier, check the model, print the verdict)
into a process supervisor: it launched sessions in their own process groups, tracked and killed
descendants, watched transcript growth for stalls, resumed or restarted sessions, stitched torn
transcript parts, gated box-wide concurrency and ran a background image shrinker. Each of those
is a concurrency or lifecycle problem with its own races (processes exiting mid-scan, reparenting,
replayed events, files read while being rewritten, substring matches on command lines). A shell
script tested with fake agents cannot cover those races well, so every round found the next one.

Most of that supervision is now owned by Box Ops: `longrun` detaches, resumes, detects stalls from
real activity, enforces memory limits and kills whole job trees, and `boxops`/`heavy` enforce the
box-wide cap. The runner was duplicating a supervisor that already exists.

## Structural fix

The simplification PR (receipt probability-quality-gates-2026-10-15) cuts `agent-run.sh` down to the model and grok guards and the verdict output, and
deletes the code `longrun` now covers: process-group and descendant tracking, the stall watchdog,
the resume loop and transcript stitching, and the concurrency gate (Box Ops' cap stays the first
layer). What stays is one session per call: `--resume <id>` (issued by `longrun`), a fresh prompt
after a `NonRetriableError`, and one check of the last line (a complete line without a newline is
kept; a torn one fails closed if it carried a verdict or model id, else is cut).
Fake-agent tests that still apply (model guard, transcript model scan, verdict parsing) are kept.
Lesson recorded: supervision belongs to one owner; a task runner should not grow a second one.
